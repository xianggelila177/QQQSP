# QQQSP 2.2 部署与升级说明

本包为完整源码与构建产物交付，不需要拼接之前的文件或重新编译前端。建议从现有 2.1 安装目录升级；使用同一域名和服务路径，保留自选、配置及恢复数据。

## 一、环境与包内容

概况：运行只需要 Node.js 22.16 或更新版本与系统标准工具；持久服务安装需要 Linux、systemd 和管理员权限。Node.js 24 可作为目标运行环境，但本轮实际执行的测试环境为 22.16.0。

包内包括：应用后端与前端源码、已构建的 `panel.bundle.js`、Brotli/Gzip 预压缩文件、`.env.example`、安装与回滚脚本、测试代码、测试报告、逐文件 `SHA256SUMS`。

```bash
node --version
unzip qqqsp-v2.2-source.zip
cd qqqsp-v2.2
sha256sum -c SHA256SUMS
```

不需要运行 `npm install`。Python 和浏览器工具只用于开发测试，不用于服务器运行。不要在解压前用目录删除命令移除原安装。

## 二、安装或升级 systemd 服务

概况：安装器创建新 release，保留共享配置及状态，切换当前版本，检查服务是否就绪；启动失败时恢复上一版本。它不验证所有行情源是否可达，因此还需执行第三节的历史验收。

```bash
sudo env NODE_BIN="$(command -v node)" bash ops/install.sh /opt/qqqsp-v2 8568
sudo systemctl status qqqsp-v2 --no-pager
```

安装路径已不是 `/opt/qqqsp-v2` 时，请填写真实路径，不要无意创建第二个安装。已有 `shared/.env` 时保留其端口与其他配置，命令中的 `8568` 仅决定首次安装端口。

| 位置 | 用途 |
|---|---|
| `/opt/qqqsp-v2/shared/.env` | 持久配置，升级不覆盖 |
| `/opt/qqqsp-v2/shared/state/` | 行情恢复文件 |
| `/opt/qqqsp-v2/shared/logs/` | 应用日志 |
| `/opt/qqqsp-v2/current` | 当前 release 链接 |
| `/opt/qqqsp-v2/previous` | 上一 release 链接 |

若 Node 在 `/root/.nvm/` 下，服务用户可能没有执行权限。安装器会报告错误；请先把 Node 安装到服务用户可执行的系统位置，再设置 `NODE_BIN`，不要给整个 root 主目录开放权限。

安装器继续使用 `qqqsp-v2.service`；会重启这个服务，但不会停止名称不同的旧版服务。它不会更改 Nginx、cloudflared 或 DNS。

## 三、必须分别检查服务与历史

概况：服务能启动与历史能加载是两项不同的验收。第二条检查实际 `/api/history`，不是查看缓存报价里是否含有旧的日线数组。

从解压目录运行，端口与现有 `.env` 保持一致：

```bash
node ops/smoke.mjs http://127.0.0.1:8568
node ops/history-smoke.mjs http://127.0.0.1:8568 NVDA,MRVL
# 韩国普通股也可单独检查
node ops/history-smoke.mjs http://127.0.0.1:8568 000660.KS
```

历史检查逐一测试日、周、月、年，确认返回的证券、周期、数据状态及开高低收有效，并打印来源、条数和数据日期。只执行一轮，不循环冲击来源；某证券失败或冷却时停止该证券后续周期检查并以非零状态退出。该检查不向生产服务注入任何测试价格。

首次年线可能需要比日线更长的来源请求；冷启动或多卡片排队会更慢。输出 `ok: true` 才代表这次网络环境下列出的历史检查通过。`readyz` 成功、来源返回 `PENDING` 或页面出现数字，都不代表日/周 K 已通过。

如果失败，请保留打印的来源、错误和 `retryAt`，等待冷却后再检查；不要连续刷新，不要删除状态文件企图绕过限流。可以查看：

```bash
sudo journalctl -u qqqsp-v2 -n 100 --no-pager
```

## 四、切换域名与刷新前端

概况：同路径升级且端口未变时通常不用改隧道；首次并行部署则需把现有反向代理的本地目标指向新端口。

默认服务只监听 `127.0.0.1`。已有 cloudflared 或反向代理继续转发至 `http://127.0.0.1:8568`，并允许事件流持续输出。通过实际域名再检查日 K、周 K、月 K、年 K 和分时模式。

Nginx 事件流位置应禁用响应缓冲，例如放入现有站点相应配置：

```nginx
location /api/stream {
    proxy_pass http://127.0.0.1:8568;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 90s;
}
```

该片段不是完整站点配置，不应覆盖原有 TLS 或其他 location。已有正常的 SSE 配置不必重复修改。

本版缓存资源序号为 **75**。部署后接受页面的更新提示或强制刷新，确认资源地址包含 `panel.bundle.js?v=75`、`style.css?v=75`。已经安装为应用的窗口需要关闭后重新打开。不要清空站点存储，自选、名称与币种偏好在 localStorage 中。

图表验证：NVDA 选择日 K、MRVL 选择周 K，应显示真实历史蜡烛或明确来源错误；分时选择“来源历史”时画折线，选择“报价采样”时明确标识“非完整历史”。来源只有一个真实点时只显示一个点，不应补造整天曲线。

## 五、不使用 systemd 的直接运行

概况：此方式适用于现有进程管理器或先行试运行。构建产物已经包含。

```bash
cp .env.example .env
# 根据环境编辑 HOST、PORT；默认 HOST=127.0.0.1，PORT=8567
bash start.sh
```

没有反向代理但需要外部访问时，可显式配置 `HOST=0.0.0.0`，并由你现有的访问控制或防火墙限制暴露范围。本程序不提供用户认证系统；不应直接作为无限制公共行情服务。

公共来源无需配置账户密钥。Alpaca、Finnhub 保持默认关闭；已有凭据可保留在服务端 `.env`，不要写进前端或发给其他人。

## 六、回滚与验证边界

概况：安装成功后保留上一 release，回滚不删除共享数据。第一次部署没有上一 release 时，应回到仍保留的旧服务或原备份。

```bash
sudo bash ops/rollback.sh /opt/qqqsp-v2
sudo systemctl status qqqsp-v2 --no-pager
```

本次没有登录你的服务器，没有执行真实 systemd 安装、域名切换或真实行情来源联调。已完成的是交付源码的自动测试、浏览器测试及干净解压后的本地启动验收。上游网站可能限流、变更响应或不覆盖某证券，本版会切源、冷却或显示明确状态，不会伪造历史数据。

## 七、部署完成标准

概况：完成安装、真实历史检查、域名页面与资源版本检查后，再把新版本作为日常入口。原服务或上一 release 应保留到确认实际交易时段表现正常。

本交付包包含全部运行文件，不需要将零散修复复制进旧包。
