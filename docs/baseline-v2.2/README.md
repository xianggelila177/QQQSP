# QQQSP 2.2：图表修复交付版

本包包含完整源码、构建后的前端、预压缩资源、配置模板、部署与回滚脚本，以及故障复现测试。面向单用户、单进程使用；没有数据库、Redis、前端框架或 npm 运行时依赖。运行要求 Node.js 22.16 或更新版本。

## 一、开始部署

概况：前端已构建，不需要 `npm install`；升级应通过安装脚本完成，保留现有配置和状态。

```bash
unzip qqqsp-v2.2-source.zip
cd qqqsp-v2.2
sudo env NODE_BIN="$(command -v node)" bash ops/install.sh /opt/qqqsp-v2 8568
node ops/smoke.mjs http://127.0.0.1:8568
node ops/history-smoke.mjs http://127.0.0.1:8568 NVDA,MRVL
```

服务名保持 `qqqsp-v2`。现有安装路径不同，应替换上面的 `/opt/qqqsp-v2`。升级时保留 `shared/.env` 中的已有端口；最后两条命令应使用实际端口。安装脚本不修改隧道或反向代理配置。

完整步骤、直接启动方式、前端缓存检查与回滚见 [部署说明](部署说明.md)。

## 二、本版修复

概况：修复的是来源失败、历史加载状态和图形选择之间的实际问题，不靠虚构数据掩盖空白。

| 问题 | 处理 |
|---|---|
| Yahoo 历史限流后日 K、周 K 全部不可用 | 美国市场增加 Nasdaq、东方财富独立历史适配；中国内地、香港历史增加东方财富候选；保留韩国 Naver 与原有其他市场路径 |
| HTTP 200 但历史为空、证券不匹配 | 有效性和证券身份检查不通过时切换适用来源 |
| 分时携带开高低收字段就被误画成蜡烛 | 明确根据所选周期绘制；分时始终折线，日/周/月/年使用开高低收 |
| 来源分时和本次报价采样混淆 | 增加“来源历史／报价采样”选择，注明来源日期、延迟和非完整历史；同日延迟历史不再悄悄被替换 |
| 历史翻到尽头后已有 K 线消失 | 空的上一页只标记分页结束，保留已有数据 |
| 多卡片排队误判超时 | 历史执行超时从开始执行计；报价任务不等待历史 |
| 日线切到年线复用不够长的数据 | 检查请求覆盖范围，共享短窗口后按需扩大；不强行把短历史当成长历史 |
| 来源限流后重复点重试 | 服务端共享冷却，前端显示剩余等待时间并禁止提前重复请求 |

服务首次显示报价时不再预取全部日线；用户打开日、周、月、年 K 时才调用历史接口。四个周期共享同证券原始日线缓存。报价年龄仍由独立的一秒显示时钟更新。

## 三、验证与边界

概况：本版记录可复现的自动化结果，同时区分测试样本与真实来源。

[测试报告](docs/TEST-REPORT.zh-CN.md) 列出本版实际执行的完整回归、图表浏览器测试和解压启动检查。[实现说明](docs/IMPLEMENTATION-NOTES.zh-CN.md) 列出文件级变更；[来源说明](docs/SOURCES-2.2.zh-CN.md) 说明接口格式与限制。

开发检查：

```bash
node scripts/build.mjs
node scripts/verify.mjs
node tests/run.mjs
# 浏览器验证额外需要 Python Playwright 和 Chromium，仅用于开发
python3 tests/v2/chart_browser_check.py
```

网络来源的真实可达性必须在目标服务器执行历史检查，不能仅凭 `/readyz` 判断。本版不会保证免费来源永不返回 429，也不会造出缺失的历史蜡烛。全部来源失败时明确提示原因和冷却时间。旧版文档与测试证据已归档，不作为本版测试结论。

## 四、交付确认

概况：`lib/` 是后端源码，`public/modules/` 和 `public/app.js` 是前端源码，`public/panel.bundle.js` 是配套构建产物，`ops/` 是部署与验收工具。所有运行必需文件已包含在包中。

前端资源版本为 **75**，应用版本为 **2.2.0**。部署后应确认网络面板或页面源码加载的是 `panel.bundle.js?v=75`；无需清空自选数据。
