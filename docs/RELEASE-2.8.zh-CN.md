# QQQSP 2.8 本轮完整整合说明

## 一、概况

本轮以会话内2.7完整ZIP为可复现基础，纳入上一轮提供的五个实际修改模块及两组测试，并补齐应用组装、HTTP／事件流、前端接收、配置、测试样本和部署工具。上轮工作目录只有公开附件可恢复的文件，没有把上轮全部日志直接当作本轮验收。所有最终结果都由本轮完整程序集重新执行。

## 二、生产链路整合

| 链路 | 当前实现 |
|---|---|
| 宏观方向 | macro-analysis调用macro-transmission，先区分事件再选择资产渠道，保留CPI可比实际／预期的优先级 |
| 证据显示 | 前端展示原句、报道／预期／观点／情景及条件；仅因子更新时不重建无变化新闻条目 |
| 历史生命周期 | app显式创建historyPrewarm，随服务器启动停止，保留最近一次自选而不把断开连接当作删除名单 |
| 历史API | /api/history优先取已准备结果；/api/history/bundle用于缓存和登记；/api/history/status输出诊断 |
| 历史推送 | 在原有行情SSE上增加history事件，按变化标的发送，无第四条独立长连接 |
| 前端缓存 | 四档hydrate入各卡缓存，未变版本复用数组，拒绝源时间倒退；已显示旧页不因空分页消失 |
| 调度和存储 | 单个工作任务按最早到期轮转，最近名单和原始日线写入原子检查点，关闭页面继续运行 |
| 性能 | 日期格式化器按时区复用；避免四档独立取源，图表回退刷新共用控制器计时器 |

HTTP缓存读取不绕过来源429。日度行情不会转换为新分钟行情；源检查时间不会被当成成交时间。源码没有新增运行时第三方依赖。

## 三、额外发布检查

本轮另外覆盖：未启动就stop不能覆盖磁盘状态；长任务不能让后排标的长期得不到处理；清空最近自选后重启不能复活旧名单；四档共享取源、前端数组复用和旧快照拒绝。普通服务冒烟脚本通过history=off读取SSE，不把诊断中的QQQ/SPY替换成用户的后台历史名单。

原先与历史无关的宏观／报价应用测试现在显式停用新历史后台，并使用隔离路径；新增历史生命周期、完整浏览器以及生产启动验证仍测试后台默认启用。没有删除断言或新退役原测试来取得通过。

## 四、保留限制

没有把复杂项目整体重写成新框架。应用入口、卡片视图和快照服务仍有可维护性债务，本轮只完成交付所需的模块边界；不宣称“所有架构和性能问题已消失”。语义规则有覆盖边界，预测、缺少一致预期、普通公告仍可能保持待核验。背景准备完毕后的即时读取不适用于第一次没有任何历史数据的冷启动。

本包不承诺公共来源永不失败，不把受控浏览器测试当成外部来源接通或投资模型有效性。测试报告逐项说明已经执行及尚未执行的内容。
