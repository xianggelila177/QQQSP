# v68 分时图与最新报价同步

## 复现

用户报告分时比最新报价落后约半分钟。v66线上QQQ样本最新报价718.01、时间14:41:44Z，历史末点717.81、时间14:41:19Z，相差25秒。另一次45秒连续观察中，QQQ/SPY报价分别变化5/6次，历史末点各仅变化1次。实际浏览器测试把这一差异固定复现为718.01对717.81。

快照轮询约2秒，历史富化约60秒，旧前端只渲染历史。原有full内容变化、same尾点变化和窗口跟随测试均通过，不能把所有延迟归咎于画布重绘或CV版本。

## 修复契约

历史分时数组、内容版本、成交量和日K保持原始来源语义。新增独立intradayLivePoint，携带报价原单位的c、真实t、source、currency、交易所当地日期；v为null，不生成OHLC。它是“最新报价点”，不是逐笔成交记录，也不承诺提供者无延迟。

仅有效且未过期、单位匹配、同一交易日期/当前有效交易时段的报价可生成报价点。未来时间、倒退时间、旧恢复数据和不匹配单位不得进入图表。空历史或跨交易日不拼接昨天的曲线。前端最多维护一个展示末点，后续快照替换该点；拖看历史时不抢回最新视窗，日K不受影响。

图表聚合新鲜度由各自字段的新鲜度合成，不再把日K较长缓存周期套用分时较短阈值。历史观察时间与来源检索时间分开记录；只在当前REGULAR有效交易时段比较历史缺口，容忍5分钟桶起点、已声明来源延迟和抓取周期。闭市后提供者的更新时间不能被误认作最新成交时间。

收盘转换触发一次补抓；若命中旧REGULAR缓存，保留待收尾状态并使用既有有界退避重试，成功检查后结束。历史抓取不改为每2秒，没有额外常驻逐秒行情源。

## 回归与验收

测试覆盖快慢数据不同步、同时间戳重绘、full/same协议、独立报价点替换、单位/来源/时间/跨日保护、成交量与日K隔离、历史视窗、字段聚合过期、5分钟桶保护及收盘缓存窗口重试。

ops/intraday-live-smoke.mjs用于正常交易时段：采样QQQ/SPY，确认每份响应的最新报价点与price/quoteAt相符，历史CV可保持same且报价点继续更新。要求观察到实际报价变化；闭市或无变化窗口不伪报动态验收成功。最终发布仍需完整测试、分层覆盖率、Linux原生检查、可重复工件、独立预发布与线上验证。

## 并发版本处理

实施期间检测到用户暂停的Kimi任务已发布另一份v67。本轮发布保护阻止了覆盖，改用v68避免缓存版本冲突。该任务对PRE/POST/AUCTION统一放宽15分钟的策略未纳入本轮：它不解决REGULAR分时同步主诉，且未具备来源检查时间时也可能误判正常。本轮保留原有时效检查，独立修复图价同步；保留已验收v66作故障回退。

## 动态验收的来源交接边界

首轮生产动态验收捕获历史源比快报价新2秒的样本，应用正确地没有生成倒退点，旧验收却将其视为失败并自动回退v66。重现测试补充这种合法交接：仅健康报价、明确null点/unavailable状态、历史领先不超过10秒、报价年龄不超过30秒且双方时间非未来时单独计数。仍必须每个证券至少3个有效匹配点、1次匹配点变化和1次带匹配点的CV same；全交接或静态窗口不能通过。应用历史和报价点保护未放宽，也未修改应用运行代码。
