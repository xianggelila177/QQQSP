# QQQSP 2.1 · 可部署源码包

## 一、版本概况

本包包含完整服务端源码、已构建的前端与预压缩资源、配置模板、部署/回滚脚本和测试。直接运行，不需要 npm install，不需要重新构建。产品版本 **2.1.0**，前端缓存版本 **74**。

采用单用户、单进程、原生 HTTP 与浏览器原生脚本。没有数据库、Redis、前后端框架或 npm 运行时依赖。保留原来的自选、市场目录、币种、五档图表、资讯、恢复文件和离线静态资源。

本版新增：多市场公司搜索、韩国本地历史、Sina 批量报价、开市一秒调度、主源失败后的备源持续采集。缺少历史时显示已收到的真实报价点，明确标注非完整历史，不凭空补齐走势和成交量。

## 二、部署

### 2.1 Linux 长期运行

要求 Node.js **22.16 或更新版本，推荐 24**，以及 Bash/systemd。两种 Node 版本均完成本包测试。运行时不需要 Python；Python 与浏览器工具仅用于开发测试。

解压后执行：

```bash
cd qqqsp-v2.1
sudo bash ops/install.sh /opt/qqqsp-v2 8568
node ops/smoke.mjs http://127.0.0.1:8568
```

安装器创建或升级 `qqqsp-v2.service`，仅复制运行必需文件；不停止其他名称的旧版服务，不修改 cloudflared 或反向代理配置。升级同一 `qqqsp-v2.service` 会有一次短暂重启，并保留配置、日志和恢复数据。

若 sudo 找不到 Node，显式指定所有用户可执行的 Node 路径：

```bash
sudo NODE_BIN=/usr/local/bin/node bash ops/install.sh /opt/qqqsp-v2 8568
```

Node 不能仅位于 root 私有且服务用户不能访问的目录。安装脚本会检查这一点，不会偷偷下载或替换系统 Node。

服务启动后，将现有隧道/代理的本地目标设为 `http://127.0.0.1:8568`。保持原域名有助于保留浏览器内的自选、名称、币种和列数设置；部署后强制刷新一次或接受离线应用的更新提示。

```bash
sudo systemctl status qqqsp-v2 --no-pager
sudo journalctl -u qqqsp-v2 -n 50 --no-pager
sudo systemctl restart qqqsp-v2
```

配置保存在 `/opt/qqqsp-v2/shared/.env`。安装器首次设置端口，升级时不覆盖已有配置；已有配置里的端口优先于第二个安装参数。

### 2.2 不安装服务的直接运行

```bash
cp .env.example .env
# .env 中把 PORT 改成未占用的端口，例如 8568。
node --env-file=.env server.js
```

也可以运行 `bash start.sh`。默认只监听回环地址；同机代理可直接连接。如需由另一台设备直接访问，请在受控网络中设置 `HOST=0.0.0.0` 并配置防火墙。程序没有用户登录系统，不建议把管理诊断端点不加限制地暴露到公网。

### 2.3 升级与回退

从新源码目录重新执行安装命令即可升级。已安装过上一部署版本时：

```bash
sudo bash ops/rollback.sh /opt/qqqsp-v2
```

首次安装没有上一部署版本，回退时将隧道改回仍保留的旧站端口。安装器用 `/readyz` 验证服务启动；上游暂时不可用不会被误判为程序无法启动。应另外检查页面的数据来源与报价时间。

## 三、数据刷新与配置

默认使用公共网站来源，不配置付费密钥也能启动。公共来源是否可达、是否覆盖特定证券，取决于部署地区和上游状态。生产入口从不加载测试样本。

```dotenv
POLL_MS=1000
POLL_PRIMARY=sina
REALTIME_SNAPSHOTS=1
```

美国股票主链路：新浪批量 → 腾讯批量 → Naver；中国内地/香港：腾讯批量 → 新浪批量；韩国普通股：Naver 本地批量；其他市场保留既有来源。改 `POLL_PRIMARY=tencent` 可切换美国股票主源，然后重启服务。没有自动代理轮换、IP 轮换或绕过配额。

开市按一秒目标调度同源批量请求，不是每张卡独立发请求；正在执行的批次不重叠。盘前/盘后同样使用活跃调度。休市降低频率，重新开市立即恢复。不同市场组独立执行，慢历史不会阻塞正常报价。

**一秒是调度与显示目标，不是来源授权或价格新鲜度保证。** 来源返回七秒等采集间隔时必须遵守；429 的 Retry-After 优先于一秒目标，进入来源共享冷却；备源继续按自己的节奏采集，不能承诺永不出现 429。

浏览器连接正常时由服务器推送缓存变化，不做常态行情轮询；断流时读取自有接口兜底。报价年龄独立每秒更新，不触发网络，不依赖 Worker。`quoteAt` 是来源成交时间，`sourceCheckedAt` 是成功检查时间；心跳、成功请求和同一个旧成交不会把年龄清零。来源只有分钟精度时界面会标注。

Alpaca/Finnhub 适配器继续保留，默认关闭，配置自身有效凭据后使用。密钥只放服务端。未在本次验收中验证真实账户权限。启用单一交易所来源不等于获取全美综合行情。

## 四、韩国股票与图表

“海力士”“SK海力士”“SK Hynix”返回 `000660.KS`（韩元、韩国普通股）与 `SKHY`（美元、美国存托证券）两项；按证券代码去重，不按公司名称合并。`000660`、`005930` 等已收录六位代码可以直接搜索。其他韩国六位代码需上游核验具体代码和市场，未确认时不猜 `.KS` 或 `.KQ`。

韩国普通股的分时与日线优先使用 Naver 韩国历史接口；美国存托证券不借用韩国本地历史。分钟数据按实际来源时间与累计成交量差值解析。分时约一分钟缓存、日线约五分钟缓存，失败冷却时保留既有数据并标注状态。

历史缺失时，有有效报价便可显示一个真实点，之后积累本次打开收到的报价。每分钟保留最后一笔实际观察价格，当前分钟随新观察更新；这不是完整分时、不是逐笔历史，也不是历史 K 线。数据断档不插值补齐，成交量未知显示缺失。上一交易日历史不会与新盘前报价拼成一条连续曲线。
