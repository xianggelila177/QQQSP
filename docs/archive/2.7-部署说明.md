# QQQSP 2.7 源码交付与部署方案

版本：应用 2.7.0；静态资源 80。方案日期：2026-09-11。

## 一、部署概况

本包提供完整源码、预构建及预压缩前端、配置模板、安装器、回滚脚本和可复现测试。运行仅依赖 Node.js 22.16 或更新版本，不需要 npm install。建议沿用现有单进程部署，不新增数据库、Redis、定时任务服务或其他消息系统。

宏观后台默认启用。服务启动后独立检查五项跨资产观察、资讯及已配置的经济日历。页面是否打开不影响采集；展开页面只是读取已有快照。采集间隔默认：因子 30 秒，资讯 60 秒；每个上游仍有自己的缓存、声明间隔及失败冷却。股票报价年龄继续独立每秒更新。

本次无需新增密钥或更改现有共享配置。2.7完整包含上一轮2.6宏观来源修复，不需要先安装2.6或合并补丁。新增公开日度参考仅作为明确标注的备用资料，不等于实时期货、美元DXY指数或分钟收益率；其他公开来源和经济日历权限保持原样。旧状态会由代码重新评估，无需删除宏观检查点或浏览器自选。仅持久化恢复文件中缺少新版时间契约的旧Nasdaq分时数组会被失效并重新获取；报价、日K、其他来源和宏观状态保留。

本版在保留压缩/编码/宏观加载修复的基础上，修正Nasdaq分时横坐标误作UTC、冬夏令时、缓存遗留及最右侧时间刻度的问题。实际变更与可复现测试见 docs/REPAIR-2.7.zh-CN.md。

## 二、部署前检查与备份

本节针对已有 v2 安装升级。首次安装无需备份不存在的目录。不要在说明或截图中公开共享配置，因为其中可能有行情或通知密钥。

```bash
node --version
command -v node
systemctl --version
```

Node 必须至少为 22.16，且 qqqsp 服务用户有权进入其目录并执行。安装器会检查这一点。仅装在 /root/.nvm 且父目录禁止其他用户访问的 Node 不能直接供服务使用；应准备可供服务用户执行的 Node 路径，并用 NODE_BIN 指定。本包不附带 Node 二进制，也不执行网络安装脚本。

已有安装在 /opt/qqqsp-v2 时，记录当前发布位置，并备份共享配置与状态：

```bash
sudo readlink -f /opt/qqqsp-v2/current
# 已有服务时短暂停止，可得到一致的宏观状态检查点。
sudo systemctl stop qqqsp-v2
sudo tar -czf "/root/qqqsp-shared-$(date +%Y%m%d-%H%M%S).tar.gz"   -C /opt/qqqsp-v2 shared
sudo systemctl start qqqsp-v2
```

备份包含配置、状态和日志，应仅由管理员保存。不要删除原发布目录；不要用 .env.example 覆盖已有共享配置。

## 三、安装或原地升级

上传完整 ZIP 至服务器后执行。示例沿用 /opt/qqqsp-v2 和 8568，已有路径或端口不同则用实际值。

```bash
unzip qqqsp-v2.7-source.zip
cd qqqsp-v2.7

# Linux 可选：核对包内每个文件。
sha256sum -c SHA256SUMS

sudo env NODE_BIN="$(command -v node)"   bash ops/install.sh /opt/qqqsp-v2 8568

sudo systemctl status qqqsp-v2 --no-pager
```

安装器只把运行所需源码及资源复制进新的 releases 子目录，不把测试样本或截图装进运行目录；随后切换 current 符号链接，创建或更新一个 qqqsp-v2.service。既有同名 v2 服务会重启。其他名称的旧版服务不会由该安装器停止。

首次安装的端口由第二个参数指定；升级时 **shared/.env 中的 PORT 优先**。旧配置缺少新增宏观键时，代码会采用本版默认值，默认仍为后台启用。readyz 检查失败时安装器尝试切回上一个 current，已启动且 ready 不代表真实行情源全部可用。

安装后的目录：

```text
/opt/qqqsp-v2/
  current -> releases/本次发布/
  previous -> releases/上一发布/    # 成功升级后才有
  releases/
  shared/
    .env
    state/quotes.json
    state/macro.json
    logs/panel.log
```

默认宏观持久化文件为 /opt/qqqsp-v2/shared/state/macro.json，权限及所有权由服务用户维护。原子检查点保存资讯、有限的采样、已采集发布前预期和通知去重状态，不使用数据库。

## 四、后台监控配置

以下配置写在 /opt/qqqsp-v2/shared/.env，不是在浏览器中填写。先查看旧值，再修改，避免同一键重复出现。

```dotenv
MACRO_BACKGROUND_ENABLED=1
MACRO_STATE_PATH=./state/macro.json
MACRO_CONTEXT_MS=30000
MACRO_NEWS_MS=60000
MACRO_WEBHOOK_URL=
MACRO_WEBHOOK_TOKEN=
TE_API_KEY=
```

MACRO_BACKGROUND_ENABLED=1 表示随服务器独立采集。设为 0 是明确停用后台，不符合本次持续监控目标；MACRO_STATE_PATH 留空则只关闭持久化，不关闭采集。相对路径以当前服务工作目录为基准；默认 state 已链接到 shared/state，不要误改到只读或临时发布位置。

MACRO_CONTEXT_MS 允许 30000～600000，MACRO_NEWS_MS 允许 60000～900000，单位毫秒。不要为了“秒级新闻”调高上游压力；前端报价年龄的一秒计时与资讯读取不是同一件事。上游 429 会遵守等待时间，人工重试不会绕过冷却。

TE_API_KEY 为可选自有经济日历权限。未配置时显示未启用，其他公共资讯和因子仍运行。没有提前收集到的发布前预期不会补造。恢复文件中的旧记录会进行日期及结构检查，不把服务器重启时间当成新闻或成交时间。

修改后：

```bash
sudo systemctl restart qqqsp-v2
sudo journalctl -u qqqsp-v2 -n 60 --no-pager
```

## 五、在线推送与浏览器关闭后的通知

本节区分页面连接与外部通知，避免把后台采集误认为手机必然收到通知。

正常页面使用 /api/macro/stream 独立事件流。折叠宏观区域不关流；断线后读取 /api/macro/snapshot 兜底，恢复后接收新快照。完全关闭浏览器时没有页面可接收，但服务器持续采集，重新打开立即读取已经积累的数据。

需要浏览器关闭后通知到其他系统时，配置自己的 HTTPS JSON 接收端：

```dotenv
MACRO_WEBHOOK_URL=https://你的接收端/qqqsp
MACRO_WEBHOOK_TOKEN=你的接收端令牌
```

程序 POST application/json，可选发送 Authorization: Bearer 请求头。正文结构：

```json
{
  "type": "qqqsp.macro.focus",
  "id": "稳定事件标识",
  "title": "事件标题",
  "link": "原始报道地址",
  "publishedAt": 0,
  "assessment": {"importance": "focus", "impacts": []}
}
```

这是自定义通用接收格式，并非企业微信、钉钉或 Telegram 现有机器人的专用协议。只有能够接收该 JSON 的地址可以直接配置；其他平台需要由你控制的转换接收端。令牌不传到前端。接收端应快速返回 2xx，并按 id 去重。

第一次取得的资讯作为基线，不把积压历史批量发送。仅新出现、两小时内、满足重点条件且有正向／负向／分歧影响的事件进入通知队列；普通调查、背景和仅待验证项不会刷屏。失败退避，最多五次，放弃后不在下次轮询重新入队。发送间隔至少 30 秒；发生“接收端已收取但响应丢失”时可能重试，接收端按 id 去重，不能宣称严格一次投递。

未配置接收端时，没有邮件、短信或系统离线通知。本版未实现浏览器原生 Push API 订阅。本次没有向任何真实通知地址发送事件或配置外部账户。

## 六、上线验收

验收分为服务可运行、后台独立调度及真实来源可用三层；前两层成功不能替代第三层。

```bash
# 1. 正式服务、资源版本与宏观事件流
node ops/smoke.mjs http://127.0.0.1:8568
node ops/macro-smoke.mjs http://127.0.0.1:8568 --stream

# 2. 关闭所有面板页面后观察默认 65 秒；对比新闻/因子轮次递增
node ops/macro-smoke.mjs http://127.0.0.1:8568 --background

# 3. 先导出来源错误、时间基础及备用类型，不触发强刷
node ops/macro-smoke.mjs http://127.0.0.1:8568 --diagnose

# 4. 核对这台服务器的真实资讯及五项因子
node ops/macro-smoke.mjs http://127.0.0.1:8568 --live

# 5. 核对报价时间与分时数据（输出均为北京时间）
node ops/chart-time-smoke.mjs http://127.0.0.1:8568 LITE,AAOI

# 6. 可选：回归股票历史与期货
node ops/history-smoke.mjs http://127.0.0.1:8568 NVDA,MRVL
node ops/futures-smoke.mjs http://127.0.0.1:8568 --live NQ00Y.FUT
```

后台验收默认等待 65 秒。你修改了轮询间隔时，使用 --seconds=观察秒数（1～900，选大于新闻及因子的实际间隔），例如 --background --seconds=310。该检查确认调度递增，不要求每轮有新成交。网络任务一直未结束也会使轮次不增长，应排查连接和超时，而不是增加并发。

--diagnose 只读取服务端诊断，即使上游不可达也输出结果；不将该模式退出成功当作行情验收。--live 另要求资讯和五项显示数据有效，可接受明确标注的日度资料，因此通过也不代表五项均为实时原合约。输出包含 quality 的近期来源时间数、服务器观察数、日度参考数，以及每项 source/status/quoteAt/sourceCheckedAt/daily/comparisonBasis/diagnostics。全部真实来源不可用时会非零退出，这是来源验收失败，不是“ready 服务完全没有启动”。日度收益率或替代观察值可以显示，但不因此变成实时原合约行情；必须继续看口径说明。

成功升级后前端资源为 panel.bundle.js?v=80。正常刷新页面并接受已有更新提示即可，不要清空 localStorage，否则可能丢失自选。若仍见旧版，核对反向代理和当前运行目录，不要首先删除用户数据。

### 6.1 如何验收这次四小时错位修复

同一条来源时间为2026年9月11日美东10:16的样本，应显示北京时间22:16，而不是18:16。时区转换在Nasdaq适配器完成，前端统一以Asia/Shanghai显示；不根据当前价格时间强行推算历史。冬季按来源日期自动处理，不能统一加四小时。日、周、月、年K线按交易所交易日归组，不整体平移日期。

`chart-time-smoke.mjs`最长读取本地快照30秒，输出quoteAt/historyAt、北京时间、历史差距、来源时间契约及陈旧状态。它不强制刷新上游，也不要求历史分钟点与逐笔报价同秒。旧Nasdaq契约或没有数据时返回非零；新契约但真正陈旧的历史会报告差距，不能将其当作已经同步更新的证明。只有数值横坐标、没有来源时间标签时，保持原始时间且提示口径未核验，不能证明时区正确。

页面分时旁应出现“北京时间 UTC+8”，周期K线显示“交易所交易日”。如果价格22:16而历史确实只更新到22:01，应继续显示22:01并标明滞后；不能为好看把旧价格重新标成22:16。修复时无需改变服务器系统时区，也无需清空浏览器自选。

### 6.2 如何处理仍为空的来源

展开对应因子的“来源口径”，或保存以下诊断：

```bash
node ops/macro-smoke.mjs http://127.0.0.1:8568 --diagnose > macro-diagnostics.json
sudo journalctl -u qqqsp-v2 -n 100 --no-pager
```

`EAI_AGAIN`、`ENOTFOUND` 表示服务器域名解析失败，不是等十五分钟就能解决；请先检查该服务器网络和解析配置。HTTP 429 则需等待显示的最早重试时间，不建议加并发或绕过冷却。返回空行情说明该请求未覆盖品种或数据日期不合法。日度参考显示日期且不参与分钟比较，不应把它的更新时间改成服务器当前时刻。

主要来源域名包括 hq.sinajs.cn、futsseapi.eastmoney.com、push2.eastmoney.com、query1.finance.yahoo.com、bond.finance.sina.com.cn、fred.stlouisfed.org。后台按来源批量和缓存请求，备用FRED四序列共用一次CSV及十五分钟缓存，不每个页面单独采集。

所有候选都失败时保留旧价格并暂停比较，不能由程序保证目标服务器网络一定放通。本次交付没有预设代理、盗用接口凭据或提供外部绕行服务。

## 七、域名和事件流转发

沿用原来的域名与隧道可以保留浏览器同源自选。安装器不会自动修改 cloudflared、域名或防火墙；已有目标仍为相同端口通常无需改动。首次切换时先检查本地端口，再将隧道的本地目标改为 http://127.0.0.1:8568。

自管反向代理必须允许 /api/stream 与 /api/macro/stream 的长连接，不缓存或缓冲事件响应。以 Nginx 为例，合并至你的现有 HTTPS server 块，而不是整体覆盖配置：

```nginx
location ~ ^/api/(macro/)?stream$ {
    proxy_pass http://127.0.0.1:8568;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 75s;
}
```

这是配置示例，本轮没有启动或实测 Nginx、Cloudflare 隧道或证书。使用既有隧道时不必额外安装 Nginx。服务默认绑定回环地址，公网访问交给现有安全入口；状态诊断和宏观内容在当前单用户站点可读取，不要把配置文件暴露为静态资源。

## 八、回滚与运行排查

成功升级后使用新源码目录中的脚本：

```bash
sudo bash ops/rollback.sh /opt/qqqsp-v2
sudo systemctl status qqqsp-v2 --no-pager
```

回滚交换 current 和 previous 并重启服务，保留共享配置及状态，不会自动还原这些数据。首次安装没有 previous 时，应将隧道切回先前保留的旧服务。需要恢复备份时先停服务，再由管理员确认备份版本与目标路径，避免把旧配置覆盖到正在运行的新服务。

常见检查：后台显示未启用，查看共享 .env 是否有 MACRO_BACKGROUND_ENABLED=0；状态无法保存，检查 shared/state 对 qqqsp 的写权限；有价格但“时间未知”，查看来源是否真的提供日期与时区，不要强制补当前时间；调查不在“重点”，切换“全部”，背景调查不应强行标成纳指交易事件；全部来源失败，查看 /api/macro/status 和 --live 输出，等待冷却后检查网络，不能靠循环点击强刷保证解除429。

## 九、交付结论及验证边界

本包可独立启动或通过安装器升级，不需要2.5或零散补丁作运行依赖。构建、保留回归、宏观及行情浏览器测试、解压后的正式入口启动均按测试报告验收。当前最新文档是本文件与 docs/TEST-REPORT.zh-CN.md；docs/archive 和 baseline 目录是旧版资料。

没有在你的服务器执行部署，未进行真实通知接收端／付费日历账户联调、systemd安装实操、Docker构建、真实隧道及长期稳定性验收。公开来源可用性和实际新鲜度以目标服务器 --live 为准，程序不保证永不429，也不保证每个观察项每秒产生新数据。宏观标签是条件阅读辅助，不是已经验证的获利模型。
