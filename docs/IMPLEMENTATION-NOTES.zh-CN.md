# QQQSP 2.2 实现与修复记录

本版基于完整 2.1 源码修改，并把上一轮未打包的故障结论转化为实际可运行代码。保持单用户、单进程、零 npm 运行时依赖，不进行与图表缺陷无关的大规模重写。

## 一、故障复现与定位

概况：`tests/v2/chart-regression.test.mjs` 的五个用例在未修复的 2.1 上全部失败；失败路径与截图中的“报价正常而历史不可用”、分时画法不一致直接相关。

真实 HTTP 边界的用例令 Yahoo 返回 429，但让独立历史来源正常响应；原版仍报历史加载失败。其他用例覆盖空历史成功响应、携带 OHLC 的分时、已到尽头的空分页，以及前端丢失 retryAt。

## 三、保持的业务口径

概况：不使用假数据填补免费来源的覆盖缺口。

报价时间与来源检查时间继续分开，年龄没有新成交时继续增长。分时是折线，日/周/月/年依照真实日 OHLC 聚合；无成交量口径时保持未知，不把采样次数当成交量。历史来源切换会触发不同 seriesId，前端不会把不兼容来源混成一段历史。韩国普通股和美国存托证券仍是独立证券。

Nasdaq 的美国历史日期以当日 12:00 UTC 作为内部日期载体，避免以 UTC 零点编码而在纽约时区落到前一天；该载体不是虚构的成交时间。前端日/周/月/年轴使用周期日期。东方财富日线字段按日期、开、收、高、低解析，不套用开、高、低、收的错误顺序。

## 四、测试兼容调整说明

概况：未删除故障用例或新增退役套件来得到通过结果。

一项早期断言要求所有周期永远只有一个网络请求，这会使年线沿用过短日线窗口。改为验证：日/周/月共享已有范围，年线确实需要更长范围时恰好扩大一次，重复请求不增加网络次数。韩国路由测试补全其原来只有证券名、并非有效历史的样本，保留路由与身份断言。一个不必要的每卡片定时器曾导致原有时钟回归失败，现已移除，改为共用显示时钟。

部署图表检查的 CLI 已改用实际历史接口；对应的 CLI 回归样本也改为 `/api/history`，并验证三只指定证券各四种周期共 12 次有效检查，以及非法代码在请求前失败。旧报价辅助函数的所有回归断言继续保留。

历史上已有 43 个退役旧套件及其说明原样保留，不作为通过统计；本轮对保留套件与新增核心用例重新运行全量。

## 五、交付边界

概况：完整运行链路与构建产物已包含，公开来源实际可达性仍需在目标服务器验收。真实上游、systemd、反向代理和长期稳定性不是本次离线测试能够替代的。
