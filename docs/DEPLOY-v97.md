# QQQSP 2.16.1 / v97：报价状态修复

## 已知问题及复现

| 问题 | 复现条件 | 修复后的行为 |
| --- | --- | --- |
| 网站报价误报延迟 | SKHY/SOXX 报价40–120秒前，来源刚检查成功 | 与流报价使用相同的有限年龄预算，显示“本来源暂无更新报价” |
| 状态含义混淆 | 旧成交、来源超时、明确15分钟延迟共用泛化文案 | 独立说明来源检查超时、报价久未更新、来源声明延迟；保留原时间 |
| SOX 被当作盘前股票 | 周一盘前仍显示上周五指数发布值 | 显示上一发布时段数值、等待发布；进入发布窗口后仍会警告真正旧值 |
| 不同指数共用时段缓存 | 先查另一美股指数，再查 SOX | 缓存包含证券身份，不互相污染时段 |
| 缓存跨开盘状态不变 | 缓存对象保留 CLOSED，时钟进入发布窗口 | 读取时更新已核实的 SOX 时段信息，不改变报价和来源检查时间 |
| 静默流错误等待超时 | 成交120秒前、连接健康、无新成交 | API等待逻辑与输出共用时效规则，立即返回可用缓存 |
| 取得时间掩盖来源确认缺失 | sourceCheckedAt缺失或旧，fetchedAt较新 | API与健康诊断保持未核验或部分可用 |
| 无成交时 SSE 状态冻结 | 引擎未发事件，时钟越过报价年龄或开市边界 | 每15秒心跳点评估缓存，只在业务状态改变时补发快照 |

每类问题先以固定时钟、假供应商或内存输出流复现失败，再修改代码并重跑相关用例。无需真实等待5分钟、发起压力测试或依靠供应商偶发成交来验证。

## 时效边界

普通交易时段的网站与流报价年龄预算均为至少5分钟，或明确声明延迟加30秒；超过预算仍警告。这个预算是判断旧价的容忍范围，不是主动延迟推送。无新成交的短时间间隔不再当作故障；真实新报价到达后继续按原推送流程更新。

休市报价仍有14天年龄上限；未知时段不能获得无限期限。来源检查独立校验，关联 Finnhub 心跳不能刷新网站来源的检查时间。缺失、异常、恢复缓存及上游限流继续显示明确告警。未核验的延迟不标实时。页面来源检查预算还包括浏览器读取间隔，API与后端诊断使用同一服务端预算。

SOX 使用 [Nasdaq 2026 官方方法](https://indexes.nasdaq.com/docs/methodology_SOX.pdf)的美东09:30:01–17:16发布窗口；早收盘后修订时段未有足够依据的部分保持未知，不臆造时刻。规则仅作用于已核实的 SOX，不推广到所有指数。`provider-published` 的时间显示为发布时间，不标成成交时间。

## 验证与部署

新增回归：`npm run test:v97`。相关兼容检查覆盖原连续SSE、API等待与格式、指数来源、时段转换以及前端状态。仅做针对性验证，不要求全套压力或浏览器冒烟测试。

用独立 release 目录部署，保留原 `.env`、Finnhub凭据、管理员及只读密钥、自选、采样、日志和代理配置。停服务期间取得一致shared备份，再原子切换current。保留v96目录以供回滚；回滚只切换应用，不恢复旧密钥治理状态。

本版修复状态判断，不新增行情授权，不将未更新报价改成当前时间，也不保证免费来源每只证券每秒都有新数据。
