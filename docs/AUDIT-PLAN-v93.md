# v93 实施清单（修改前基线）

## 总览
以用户上传的 QQQSP-main.zip（应用 2.12.0、静态版本 92）为唯一修改基线。保留单用户、零 npm 运行时依赖、现有供应商和自选采样。先复现，再修复，不用模拟数值补齐生产数据。

## 问题与方案
|编号|问题|实施方案与验收|
|---|---|---|
|01|智能体字段缺失被直接跳过|固定财务字段目录，null/不适用/冲突显式表达；覆盖率按应有字段计算|
|02|计算输入、股本分母和来源丢失|字段级证据投影及严格 JSON Schema，禁止透传上游任意属性|
|03|没有独立盘口契约|复用 Alpaca 官方 quotes 与 snapshot.latestQuote，保留整手单位；腾讯现有五档布局用于沪深盘口，不伪造全市场报价|
|04|截图详情与七段历史默认请求混用|新增 v2 详情接口，snapshot/analysis 档位；旧 v1 保留，默认新详情不拉取历史|
|05|报价/分时/财务共用等待导致超时归属错误|独立完成状态，事件驱动加低频兜底；截止时间后分段标记|
|06|历史聚合不能翻页|v1/v2 传递 before/seriesId，同一历史服务验证游标|
|07|五十二周高低点可拼接不同时间和币种|强制来源、单位、币种、口径和观测时间一致|
|08|逐行创建日期格式化器|有界时区格式化缓存；请求当前日期只计算一次|
|09|业务模块依赖 HTTP 图表工具|抽取纯 chart-revision 模块并兼容旧导出|
|10|价格缩放重复实现|复用 currencyUnitInfo，不把未知币种默认为美元参与财务计算|
|11|财务候选反复扫描全量实时记录|按证券索引实时记录、来源列表单次构建|
|12|自选写入只判断 Origin|独立管理员校验；本机例外拒绝代理头，界面提供仅会话内管理密钥输入|
|13|公共诊断泄露证券级信息|公共来源能力仅输出汇总，详细信息保留管理员接口|
|14|持久化失败等待下一次增删|保留待保存队列，有限退避重试；鉴权失败等待用户提供密钥|
|15|详情说明不便于智能体/用户对照|同一字段目录的详情抽屉、盘口、完整性、缺失原因、JSON 导出|
|16|采样增量重复构造完整快照|复用 takeUpdates 的元数据，不再次调用全量 snapshot|
|17|发布缺少针对最新接口的证据|新增边界/安全/盘口/契约/集成/浏览器/性能测试，留存输出|

## 外部依据与范围
参考富途市场快照字段组织、Alpaca 官方报价的独立时间与 round lots 数量单位、TradingView 日期标签规范和 OpenStock 的详情交互。只参考设计，不复制 OpenStock 源码、不引入其数据库和身份框架。

- https://openapi.futunn.com/futu-api-doc/quote/get-market-snapshot.html
- https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data
- https://www.tradingview.com/charting-library-docs/latest/connecting_data/datafeed-api/required-methods/
- https://github.com/Open-Dev-Society/OpenStock

## 验收与约束
原有测试先运行；新增修复测试先见失败后见通过。生产无运行时依赖。缺少外部网络或授权时，供应商只标记为离线契约测试通过，不能写“实盘验证”。完整目录遍历与静态扫描不等于逐行形式化证明。部署不修改用户原配置、凭据、端口、持久化数据或远端仓库。
