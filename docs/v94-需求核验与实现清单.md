# v94 需求核验与实现清单

## 一、范围与基线

输入为用户上传的《QQQSP Market-Context API 改进计划》及2.13.0完整源码包。原计划归档在同目录，保留原文，不把其中错误验收条件视为正确事实。本次实现覆盖条目1～14；条目15明确要求不做服务端指标，按该要求保留客户端计算路线。版本为2.14.0／94，不采用原计划尚未实施的v93→v95排期编号。

基线全包文件清单及散列已保存，修复是增量变化，不是替换原面板。全文件遍历清单只是程序化覆盖记录，不等于已经发现所有潜在缺陷。本轮主要审计与实现边界是上述接口改进计划及其依赖。

## 二、核验纠错

| 原条目 | 核验结论 | 执行的修正 |
| --- | --- | --- |
| v92已支持daily_before/daily_series_id | 与提供的基线版本归属不符 | 以2.13.0现有分页实现为基础保留，不重新假设v92已有 |
| NVDA 2024-07-10、4∶1拆股 | 错误 | 官方事件为2024-06-07收盘后分发，2024-06-10开始按10∶1拆股后价格交易 |
| raw与split任意区间比率恒等单次拆股比例 | 条件不完整 | 同证券、同一天、同价格币种和同复权锚点，考虑累计拆股；拆股后的同日价格可一致，跨日前后还存在市场涨跌 |
| 公司行动可直接补已支付股息 | 不充分 | 需要支付窗口、币种和每股拆股基准证明；除息日或处理日不是支付日 |
| 周六下次开市必为周一 | 不成立 | 按市场时区、假日、半日市、夏令时和覆盖范围搜索 |
| 采样价格生成分钟OHLCV | 容易误标 | 输出观察柱而非交易所真实成交柱；未知volume整列null，空桶不填0价格 |
| POST条件命中返回304 | 不符合HTTP语义 | 新增条件GET/HEAD；POST匹配If-None-Match返回412 |
| Deprecation和Sunset均按RFC8594 | 不准确 | Deprecation使用RFC9745，Sunset使用RFC8594 |
| 轮换宽限期成功请求返回错误码 | 状态设计不清楚 | 宽限内成功带rotating警告头，到期才401 KEY_ROTATED |
| 突发3次与10证券批量共存 | 需明确计数对象 | 突发按请求信封，滚动60秒按证券单位，批量原子扣额 |

外部事实依据见public/market-api-guide.md末尾规范来源；其余为本次架构设计修正，不声称源规范要求采用唯一实现。

## 四、结构和部署变化

新增领域模块：context-query、context-series、action-dividends、market-calendar-api、advanced-market-data。新增HTTP设施：api-error/body/rate-limit/representation/keys/key-admin/market-routes/quote-stream。既有market-context-service和格式投影继续作为装配入口；不引入数据库、消息队列、WebSocket服务或npm生产依赖。

新增私有密钥管理页面和高级本地客户端；保持已有行情详情窗口、旧客户端和生产入口。安装器首次无配置时安全初始化密钥；升级保留旧配置、日志、自选、历史、采样和托管状态。新密钥状态回退到旧程序存在语义差异，部署说明明确要求先关接口入口并重配凭据，而不是仅回退二进制。

## 五、验证与限制

可复现测试在tests/v2/v94-*.test.mjs，完整执行日志在docs/evidence/v94；发布报告记录实测总数。模式采用同一生成器并检验正常／异常样例，不用万能additionalProperties掩盖所有辅助返回。公司行动和行情测试数据明确是离线验收样本；不会加载到生产服务器。

没有在用户服务器执行安装或切换；没有真实商业凭据，不声明供应商权限或实盘行情可用；容器构建和长期负载若未实测则单列为待部署验收。已实现有证据的股息派生算法，但当前行动源缺乏完整支付窗口证明时不会运行补值，原财务来源继续工作。

结论：完成纠正后的接口范围和安全边界，保持旧默认契约；明确将“代码能力实现”“离线验证通过”“真实授权数据可用”分开验收，不承诺所有市场字段必定有值。
