# QQQSP 2.16.3 / v99：Finnhub 密钥池与搜索优先级

## 行为

- `FINNHUB_TOKEN` 保持向后兼容，并继续作为成交流的首选凭据。
- `FINNHUB_TOKENS` 接受最多8个英文逗号分隔的 Finnhub REST 凭据；会与 `FINNHUB_TOKEN` 合并、去空白并去重。凭据只存在于服务器私有环境文件和请求头，不进入 URL、日志、前端、诊断或仓库。
- 搜索和低频财务补充共享同一个轮换池。正常请求按槽位轮换；单个槽位收到429、401、403、服务端错误或网络错误时，只冷却该槽位并有界尝试下一个槽位。所有槽位冷却时明确失败，不绕过供应商的 `Retry-After`。
- 普通远程搜索先查询 Finnhub。Finnhub 返回有效结果时直接使用；空结果或失败才查询 Yahoo、Naver、腾讯等后备来源。`more=1` 显式展开全部来源，合并时 Finnhub 结果优先并按规范代码去重。
- 本地官方目录和明确指数别名仍位于远程来源之前；期货继续走专用目录与来源。

## 配置

```dotenv
FINNHUB_TOKEN=<流式首选密钥>
FINNHUB_TOKENS=<密钥1>,<密钥2>
```

不要把真实值写入源码、提交、问题单或浏览器存储。只配置 `FINNHUB_TOKENS` 时，第一项也可启用流式连接；已有 `FINNHUB_TOKEN` 时，流式连接保持使用原值。

## 验证范围

定向测试覆盖：配置校验与去重、健康槽位轮换、429后切换及独立冷却、诊断脱敏、ETP和指数身份规范化、Finnhub命中时不调用Yahoo、空结果时回退、`more=1`展开，以及财务补充复用同一密钥池。

部署沿用独立 release、共享状态和原子链接切换。升级前备份 `.env`、密钥摘要、自选、采样、日志、systemd 与反向代理配置；升级只新增私有 `FINNHUB_TOKENS`，保留原域名、端口、管理员及只读API密钥和原 `FINNHUB_TOKEN`。
