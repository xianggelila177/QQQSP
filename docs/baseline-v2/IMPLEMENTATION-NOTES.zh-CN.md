# 实现说明：按单用户颗粒度对齐重构计划

## 一、范围概况

本说明用于交接实际代码，而不是待办计划。依据原文件 `REBUILD-PLAN.original.md` 的目标清单，以及本轮“单用户、精简、轻量、不考虑高并发”的修订约束实施。没有把原计划中 14–19 个工作日的全部分层重写和 48 小时线上观察声称为已经完成。

本次选择“保留成熟业务模块 + 替换状态与传输内核”，而不是原封不动保留 v72 再增加第二套状态。删除运行时模块级默认服务及 init 注入路径，所有应用级服务从 `createApplication` 创建；同时避免为一个用户引入用户配额、独立限流队列和更重的框架。

## 二、功能颗粒度对齐

概况：以用户能观察到的行为为验收单位；每秒文字、价格事件、历史图表、新闻加载分别管理，不混成一个高频刷新任务。

| 原计划条目 | 本版实现 | 边界 |
|---|---|---|
| G1 多市场、12 自选、时段与报价时间 | 沿用数据资产和契约；统一快照引擎与活动成员 | 不承诺所有公共网站对所有市场可用 |
| G1.5 秒级年龄 | 独立计时器；正常/静默/异常工作线程浏览器验证 | 短时前台验证，不保证系统冻结时精确执行 |
| G1.11 SSE | 变化推送、15 秒心跳、重连快照、图表 cv 增量 | 无逐笔回放数据库；重连直接恢复当前状态 |
| G1.12 推送优先 | Alpaca 订阅确认、可选 Finnhub 备流 | 没有真实密钥联调；第二源覆盖未知，默认关闭 |
| G1.13 来源注册表 | 来源、市场、传输方式、节奏及覆盖声明集中 | 既有来源解析器签名不全部强改成万能接口 |
| G1.14/G5.1 429 | 每来源串行入口，共享冷却及恢复时间 | 不绕过限流，不保证无 429 |
| G2 图表交互 | 保留五档、均线、量柱、分页、导出与实时点分离 | 原成熟图表模块保留；未整体替换图表引擎 |
| G2.8 历史多源 | Yahoo 主，A 股新浪有限窗口备源；身份变化 409 | 尚未增加第二个海外历史源，不拼接假完整序列 |
| G2.9 resize | ResizeObserver + 动画帧合并；无双路重复监听 | 保留不支持该 API 时的窗口事件兜底 |
| G3 资讯宏观 | 沿用原来源；折叠不自动请求，无后台新闻轮转 | 用户展开或手动操作仍可请求；缓存控制上游成本 |
| G4 汇率 | 默认 ECB 参考口径，近似标记；可选择市场来源 | 日度参考汇率不是实时兑换价格 |
| G5 准入与运维 | 单服务、共享状态、日志轮转、健康及来源诊断 | 不使用原多用户准入体系；不自动修改现有隧道 |
| G6 体验 | 红框删除、骨架、流状态、市场数量汇总、搜索合并 | 保留本地存储键及响应式布局；未知日历不擅自判定 |
| G7 性能 | 缓存聚合、估算预算、Brotli 预压、推送健康时零行情轮询 | 没有多用户吞吐量、CPU/RSS 百分比提升承诺 |
| G8 对象图 | 唯一应用组装根；IO 显式注入 | 没有机械重建所有目录；市场只读资产仍按原模块加载 |

## 三、429 的行为约束

概况：上游速率控制只有一个权威入口，业务模块不能通过另开请求来提前消耗冷却期。

每个主机保留一个串行 Promise 链、上次启动时间、下一允许时间与少量计数。Yahoo 的认证、查询和图表子域归为同一组。未限流时请求遵守来源下限；首个 429 到达后，同组后续请求会重新检查冷却并立即回退缓存，不让队列继续冲击网站。其他来源不被一个网站故障连带阻塞。

等待时间由服务端提示与本地退避取较晚者：支持 Retry-After 秒数/日期、速率重置时间。授权失败和服务错误也有等待，不连续快速重试。冷却结束后自然到来的下一个请求就是探测，无须额外启动探测任务或定时器。

报价来源检查时间仍独立于成交时间。断流、403、429 或只收到控制消息时，绝不能生成“新报价时间”。来源健康状态输出不包含密钥、请求 token 或完整敏感 URL。

正常情况下，上游价格流负责价格事件，网页来源负责必要的慢字段和历史；没有流式账户时退化为网站声明的采集频率。浏览器 1 秒计时、SSE 心跳和 HTTP 兜底均不强行提高网站采集频率。

## 四、轻量化取舍

概况：必要边界校验属于单用户数据正确性；多用户隔离和复杂编排不属于本次运行模型。

保留标的合法性、最多 12 个、请求超时、响应体上限、乱序/未来成交拒绝、恢复文件原子写和有界缓存。这些是防止错误数据与永久挂起，不是为高并发准备的防御体系。

不引入 Redis、数据库、用户身份、配额分配、分布式锁、统一消息总线框架、逐笔落库或多进程订阅。同一浏览器只有一个年龄计时器和一个行情事件流；服务端只有一套对象图和一个活动调度器。

缓存公共原语用于简单的 TTL/失败/SWR/请求合并；历史分页、汇率和恢复文件有不同语义，继续用小型专用模块。将所有缓存参数化成几十个开关会增加复杂度，本版没有这么做。相同原则适用于原生图表：保留已经通过回归的交互模块，而不是更换框架。

原运维资产、旧测试与旧发布工具作为可追溯资料保留，不在当前启动或部署路径。当前安装器只安装运行必需文件，服务目录不包含测试、截图及旧 relay 工具。

## 五、验收与仍需实机确认的边界

概况：交付包含可运行实现和已完成验证，但本地验证不能替代账户、隧道和真实交易时段验证。

已经验证：91 个保留回归文件、18 个新增核心测试、六视口离线浏览器交互、年龄三种线程状态、真实本地 HTTP 与 SSE、构造无网络副作用、两次完整启停、来源 429 冷却、历史缓存和序列切换、静态压缩内容一致。

未完成：真实 Alpaca/Finnhub 权限和持续流、公共网站当前地域可达性、真实 cloudflared 事件转发、systemd 安装过程、Docker 构建、48 小时观察、完整逐字段 golden schema、全部旧混合套件逐条迁移。43 个退役旧套件有显式理由及对应替代测试路径，不当作通过。

结论：当前代码可在 Node 24 环境直接启动和按附带脚本部署；建议保持原站运行，在新端口检查来源与事件流，再切换域名。这是单用户部署切换，不需要原计划的多用户灰度分流平台。
