# QQQSP 2.14.0 交付与验证报告

## 一、交付总览

本次以用户提供的2.13.0完整源码包为基线，核验《QQQSP Market-Context API 改进计划》并实施纠正后的条目1～14；条目15明确要求不做服务端技术指标，按该要求保留客户端计算。应用版本2.14.0，静态版本94。交付是完整可启动源码、已构建资源、接口文档、本地客户端、私有密钥管理、测试及验证证据，不是仅包含实施计划。

已程序化遍历基线的585个文件，清单及SHA-256在docs/evidence/v94/input-source-inventory.json。该清单不等于人工发现全部潜在缺陷。本轮完成范围是附件列明的接口需求及其实现依赖，不声称所有市场来源永远可用，也不声称项目再无未知问题。没有修改远端GitHub仓库或用户主机；没有包含真实密钥、.env、运行采样和私有日志。

## 二、先核验再实施的修正

原文的NVDA“2024-07-10、4∶1”验收条件不正确，官方事件为2024-06-07收盘后分发、2024-06-10开始按10∶1拆股后价格交易。复权比值只能比较相同证券、日期、币种和复权锚点，并考虑累计事件，不能要求拆股前后两个不同日期的市场成交价恰好等于固定比例。

采样聚合被明确命名为观察值柱，不冒充成交明细或完整交易所OHLCV。事件的除息日、处理日和支付日分开；没有完整支付窗口、币种及每股拆股基准证据时，不运行股息补值。周末下一次开市查核交易日历及夏令时，不硬编码周一。

304仅用于条件GET/HEAD；现有POST在前置条件不满足时返回412。Deprecation按RFC9745、Sunset按RFC8594生成。密钥宽限期间成功返回轮换警告头，24小时后旧密钥返回401 KEY_ROTATED。批量配额按证券单位累计20／60秒，突发3次按请求信封计算，避免合法10只批量被突发容量永久拒绝。

官方来源及详细说明在public/market-api-guide.md末尾；原始附件保留在docs/qqqsp-api-improvements-原始输入.md，不将错误原文改写成用户原先就写对。逐项核验见docs/v94-需求核验与实现清单.md。

## 四、结构与安全修复

参数枚举提取为纯目录，文档构建不再不必要地加载运行期市场文件。领域逻辑拆为查询、序列、公司行动派生、交易日历及来源适配，HTTP设施拆为鉴权／限流／表示形式／管理／辅助路由／报价流。仍为单用户、零第三方npm生产依赖，不引入数据库或WebSocket后台。

完整回归复现了同批次证券跨毫秒缓存截止边界后，被拆成单证券上游请求的问题。增加确定性复现测试，统一批次判断时间，并保留修复前失败与修复后通过证据；没有放宽原有断言。还加强了供应商游标类型、单页数量、榜单异常行及公司行动跨页去重校验。

环境密钥替换或清空不会让已导入的旧值继续有效；同值托管密钥不会被环境配置提升权限。密钥只在管理操作成功后显示一次，服务端只保存摘要，浏览器不使用localStorage或URL存储。高级缓存最多8条，每条序列化数据2MiB；这是缓存预算，不是JavaScript堆或进程RSS硬上限。

## 六、部署与交付边界

首次解压后执行node scripts/init-config.mjs，再npm start；已存在.env时跳过初始化并保留原配置。管理入口/api-keys.html使用STATS_TOKEN；只读调用使用LLM_API_KEY或托管密钥。高级授权路线配置自己的APCA_API_KEY_ID及APCA_API_SECRET_KEY，配置存在不代表拥有SIP或历史权限。说明见部署与升级-v94.md及public/market-api-guide.md。

升级保留.env、state、logs，尤其state/api-keys.json；删除该文件可能使旧环境密钥重新启用。回退2.13及更早版本前，需要先关闭只读入口并重配凭据，不能认为旧程序理解新版本撤销记录。未在用户主机运行安装器、切换服务或反向代理。

尚未验证真实商业账户权限、目标主机部署、容器镜像构建、长期生产负载，以及原生浏览器TLS／CSP／SSE代理链路。测试行情和公司行动样本只在tests目录中，生产服务不加载。未知字段仍为null，不拿测试价格或未核验事件补齐。

## 七、结论

纠正后的附件条目已完成代码、契约、客户端、管理和离线回归实现；正常生产入口可在没有开发依赖的干净解压目录启动，并验证鉴权、密钥状态和真实缺失反馈。最终源码包另附SHA-256、完整差异补丁和独立包启动结果。代码能力实现、离线验证通过、商业来源授权和目标生产部署分别记录，不相互替代。
