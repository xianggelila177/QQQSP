## 三、故障复现和修复循环

概况：证据保留了失败过程，不只保留最后一份成功输出。

第一组五个测试在原始 2.1 上为 **0 通过、5 失败**，见 `evidence/v2.2/regression-before.log`。初次修复后为 4 通过、1 失败；剩余失败涉及不合理的“所有时间范围永远只读一次来源”断言。将其改为按实际需求验证窗口扩大一次后，五项通过。这个调整同时验证了年线不再复用过短数据，而非取消年线范围检查。

后续全量运行发现了额外时钟实例、韩国路由样本缺少有效历史字段、旧部署 CLI 测试仍假设报价接口等兼容问题。分别移除额外定时器、补全有效样本、迁移 CLI 到正确历史接口后，单项复测通过，再次执行完整回归得到第二节的最终结果。

| 可复现问题 | 验收条件 |
|---|---|
| Yahoo 429 导致美股日/周/月/年全部失败 | 真实 `/api/history` 使用独立来源返回有效蜡烛，证券、周期和纽约交易日期正确 |
| HTTP 200 但历史为空或返回了其他证券 | 不当作成功来源，尝试适用备源 |
| 分时含 OHLC 被画成蜡烛 | 分时仍是折线；价格比例尺按折线值而非无关 OHLC 范围 |
| 空的上一页清掉已有图表 | 已加载 candles 保留，标记无更多页 |
| 首次限流错误未携带冷却时间 | 第一轮失败与后续抑制请求具有同一有效 retryAt |
| 其他卡片排队造成健康请求超时 | 三项连续排队任务都能完成，执行期限从入场开始 |
| 日线期间开始加载年线 | 重新扩大原始时间范围一次，不能返回只有短窗口的数据 |
| 同日延迟历史被静默改成少量采样 | 保留来源历史；用户可明确选择采样 |
| 命名空间试探放大 429 | 主机被限流后不继续请求其他命名空间 |
| 证券身份、时间边界和数量格式 | 拒绝错证券、非法日期与未来记录；保留合法 1970 年前日期；正确解析开/收/高/低和逗号数值 |
| 部署工具只看服务存活 | 新 CLI 校验实际日、周、月、年历史和有限 OHLC；失败不反复重试 |
