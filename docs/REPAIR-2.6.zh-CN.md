# QQQSP 2.6 宏观加载故障：复现与修复记录

## 一、概况与证据范围

基线为本会话交付的qqqsp-v2.5-source.zip，修改版为2.6.0，资源版本79。用户截图显示NQ/WTI目录价格、布伦特和美元缺失、日度美债、分钟比较暂停。本轮直接运行基线模块和应用，在同类上游失败与缓存状态下建立回归，再运行完整程序及浏览器。

区分三种证据：源码缺陷可在受控输入下复现；真实本地HTTP/SSE可以验证服务和前端链路；用户服务器的具体上游响应目前未取得，不能把某一种复现故障直接称为线上唯一原因。沙箱真实出网仍有DNS解析失败，未给出“五项真实来源均已连接”的结论。

## 二、已复现的故障路径

| 故障 | 基线表现 | 2.6实现 |
|---|---|---|
| 压缩响应 | gzip的HTTP 200被直接当字符串解析，合法行情变空 | 在标准库传输层解码gzip/deflate/Brotli，校验解压大小 |
| 请求格式兼容 | 路径式list无法被只支持标准query-list的接口识别 | 新浪宏观统一使用/?list=批量代码；不声称旧路径所有环境都失效 |
| 字符编码 | UTF-8字节经latin1保留后错误按GBK解释，美元名称校验丢弃有效值 | 合法UTF-8优先解码，否则保留原GBK/转义处理；不执行响应脚本 |
| 部分行情源同时失败 | 新浪/Yahoo不可用后布伦特和美元没有可用展示 | 增加明确改名的日度参考，原实时链恢复后退出备用 |
| 日度备用锁定 | 快速源恢复后仍被旧日度优先级/十五分钟等待挡住 | 只为较高质量来源保留短期优先级；底层日度缓存不阻止重试快源 |
| 检查周期漂移 | 本轮耗时再叠加30秒，调度可能变为约60秒 | 基于本轮开始时刻计算下次到期 |
| 单源阻塞 | 一个未返回的因子阻止其他已完成结果推送 | 每因子独立任务和完成通知；共享候选等待有界且不重复创建 |
| 时间基础不兼容 | NQ为服务器观察，WTI有事件时间，始终无法形成共同窗口 | 分别保存两类采样，只使用共同基础；观察窗口明确不等于成交同步 |
| 失败状态误导 | 没有数据或已有旧数据仍显示“等待同窗数据” | 展示加载/网络失败/冷却/日度/陈旧和每个候选诊断 |
| 缓存倒退 | 更旧缓存可覆盖先前有效价格 | 保留时间较新的已有数据，失败时停止比较 |
| 日度边界 | 不存在的日历日期被日期库归一化；持久化日度无限期看似有效 | 严格核对日期，超过十四天的日度标为陈旧，不参与实时可用验收 |

日度备用不是“补齐实时行情”。布伦特现货、WTI现货、广义美元指数、恒定期限收益率保留原始名字和单位，不改成期货或DXY，不参与分钟判断。既有英国调查归组、CPI口径和否定事件规则保持2.5实现。

## 三、测试反馈与循环

第一组10个用例在2.5基线上10个失败，记录repro-before.log；修复后10个通过。继续测试发现UTF-8美元被过滤，第11例先失败再通过（encoding-before.log、repro-after-2.log）。随后增加真实应用恢复、GBK兼容、日度共享缓存、超时单飞、Brotli/解压限制等6例。发布复查又找到日度过期和不合法日期两例，先失败后修正。本轮新增共19个核心用例。

浏览器原宏观回归首次暴露：保留旧值时只有“陈旧”提示，没有说明实际来源已经失败。修复availability说明后原断言通过，未删除断言或退役测试。过程保留macro_browser_check.py.log与macro-browser-cycle2.log。

19例入口：

```bash
node --test tests/v2/macro-v26*.test.mjs
```

它们位于macro-v26-regression.test.mjs（11例）、macro-v26-recovery.test.mjs（8例），样本服务macro-v26-fixture.mjs与macro-v26-browser-server.mjs不进入生产安装目录。

## 四、真实程序与浏览器验证方式

应用测试使用实际createApplication及HTTP路由，注入受控上游：Yahoo返回429，新浪模拟解析失败/恢复，东方财富目录部分成功，FRED/Sina日线为明确的模拟资料；前端使用实际构建资源。先无浏览器采集，再折叠连接推送、展开读取、来源恢复、断网保留旧值。

浏览器运行通过测试用localhost网络转接，不是在生产代码伪造数据；它仍不是原生Safari/Cloudflare长连接完整验收。截图顶端明确标注模拟数据。实际正式server.js另做无样本启动和65秒后台观察，真实网络失败如实保留。

脚本：macro_v26_browser_check.py、macro_browser_check.py、chart_browser_check.py、futures_browser_check.py、browser_check.py、packaged-boot.py。完整通过数量与运行证据见TEST-REPORT.zh-CN.md；包外交付校验包含最终ZIP信息。

## 五、发布结论

本轮没有换掉整个系统、引入数据库或增加模型服务；重点修复传输/解析/调度/恢复和UI状态边界。部署后先查--stream，再查--diagnose和--live。若所有合法来源都因目标服务器网络或授权不可达，程序会报告并保留旧值，不会将失败改成绿色或生成假价格。
