# QQQSP 2.9 完整源码与部署包

应用版本 **2.9.0**，静态资源版本 **82**。本版以用户提供的 2.8 完整源码和《QQQSP 2.8 完整审计与修复计划》为基线，修复请求边界、实时备用源、恢复缓存、后台自选及前端交互。保留单进程、零运行时第三方依赖，不需要合并旧版补丁。

## 一、运行概况

生产运行要求 Node.js 22.16 或更新版本。已构建的前端及压缩资源随包提供，**生产启动不需要执行 npm install**。开发测试依赖仅位于 devDependencies，不参与服务运行。

```bash
bash start.sh
# 默认：http://127.0.0.1:8567
```

长期运行使用 `部署说明.md` 中的安装器。默认服务名称仍为 `qqqsp-v2`，安装目录仍为 `/opt/qqqsp-v2`；新安装默认端口 8568，升级保留共享配置中的端口。

## 二、主要变更

本版先修复跨模块行为，再做局部结构整理，没有引入数据库、缓存中间件或新的前端框架。

| 方面 | 2.9 行为 |
|---|---|
| 实时与备用行情 | 按证券成交时间、流延迟和市场时段判断可用性；心跳不会刷新旧成交时间，也不会永久关闭备用检查 |
| 历史请求 | 默认总期限 20 秒，包含排队；前端默认 22 秒覆盖响应头与正文。超时可重试，保留旧图 |
| 容量与取消 | HTTP、来源等待及历史执行队列有界；请求断开取消排队工作；行情和宏观流共享连接及缓冲预算 |
| 后台历史 | 先准备近端日线，再空闲扩展长历史；四档共用原始日线，不分别重复取源 |
| 多页面自选 | 显式保存的后台名单与在线页面订阅合并；普通只读 GET 不再覆盖后台名单 |
| 缓存与恢复 | 损坏历史记录逐项跳过；恢复存储自己创建父目录；健康行情不再同步深拷贝恢复图表 |
| 页面交互 | 存储禁用仍可启动；省流策略控制兜底请求；宏观更新保留展开与焦点；图表普通滚轮滚动页面 |
| 运维 | 版本保留数量和磁盘预算；安装器生成资源限制；容器探针读取实际端口并检查就绪字段 |

**后台名单与浏览器自选不同。** 页面新增或删除自选会明确保存后台名单；仅打开一个页面只登记该连接的临时订阅。已有 2.8 状态中的名单继续作为持久名单恢复。新安装需要关闭页面后继续维护默认标的时，执行部署文档中的显式保存步骤。

## 三、验证与文档

当前维护测试使用统一入口；旧报告仅是历史资料，不作为本版通过证据。

```bash
node scripts/verify.mjs
node tests/run.mjs
node --test tests/v2/repair-v29-*.test.mjs

# 浏览器开发环境另需 Python Playwright 与 Chromium

# 需要联网安装开发依赖的可选工具；本交付环境未完成干净安装验收

npm run test:e2e
npm run coverage
```

`部署说明.md` 给出安装、升级、显式保存后台自选、检查与回滚方法。`修复与验证报告-2.9.md` 按 R01～R24 记录实现和验证边界；`docs/TEST-REPORT.zh-CN.md` 是本版测试报告，原始证据位于交付包的 `docs/evidence/v2.9-release/`。`SHA256SUMS` 校验包内文件，压缩包自身校验值另在包外提供。
